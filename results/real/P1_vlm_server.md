# P1: 로컬 VLM 서버 점검 (2026-11-23, 실험 노트북)

> 확인한 것: 서버가 이 노트북(RTX 5070 Laptop 8GB, RAM 30GiB)에서 뜨는지, 확신 점수(logprobs), 속도.
> **확인하지 않은 것: 정확도.** `vlm-check`의 그림은 만화 같은 연습용이라 정답률은 실제 성능과 무관합니다. 정확도는 예비 데이터(P2)로 비교합니다.

## 공통 설정
- vLLM 0.34.0 (conda 환경 `vlm`, LeRobot과 분리), `--host 127.0.0.1` (이 노트북에서만 접속)
- `--max-model-len 4096 --max-num-seqs 2 --gpu-memory-utilization 0.88 --limit-mm-per-prompt '{"image": 2, "video": 0}' --mm-processor-cache-gb 1 --enforce-eager`
- `hilreview vlm-check --n-images 2` (실제 라벨링처럼 요청당 이미지 2장), Qwen3.5는 `--no-thinking` (질문문 버전 `succ-yesno-v1+nothink`)
- 다른 GPU 작업 없음

## 결과
| 모델 | 배포 | 서버 | 로딩 후 GPU 메모리 | KV 캐시 여유 | logprobs | 요청당 시간 (따뜻한 상태, 이미지 2장) |
|---|---|---|---|---|---|---|
| `cyankiwi/Qwen3.5-4B-AWQ-4bit` | 커뮤니티 AWQ 4비트 (Apache-2.0) | ✅ | 4,895 MiB (가중치 3.83 GiB) | 1.05 GiB | 있음 | 약 0.10초 (첫 요청 0.41초) |
| `Qwen/Qwen3.5-2B` | Qwen 공식 BF16 | ✅ | 4,835 MiB (가중치 4.18 GiB) | 0.67 GiB | 있음 | 약 0.06초 (첫 요청 0.35초) |
| `Qwen/Qwen3-VL-4B-Instruct-FP8` | Qwen 공식 FP8 | ❌ | 가중치만 5.7 GiB | - | - | - |

- Qwen3-VL-4B FP8은 네 가지 설정으로 시도했지만 모두 실패했습니다(기본값 → 입력 길이 2048·사용률 0.95 → 이미지 최대 512×512 → 입력 길이 1024). 가중치를 올린 뒤 비전 인코더 측정이나 KV 캐시에 필요한 메모리가 부족했습니다. **이 GPU에서는 쓰지 않습니다.**
- Qwen3.5는 생각 모드를 끄니(`enable_thinking=False`) 첫 토큰이 바로 yes/no로 나왔고, logprobs에서 p_success를 계산할 수 있었습니다.
- 속도 추정: 키프레임 약 5,000개 × 0.1초 ≈ **10분 미만** (서버 로딩 약 1.5분 별도).
- 3번 연속 요청이 모두 정상 응답했습니다.

## 남은 결정 (P2 예비 데이터로)
- 후보 2개 중 본 실험 모델 확정: **실제 예비 데이터 키프레임**으로 정확도와 가짜 성공률을 비교한 뒤, 실험 데이터를 보기 전에 고정합니다.
- **VLM 입력 해상도:** 녹화 데이터셋에는 잘라내고 128×128로 줄인 이미지만 저장되므로, VLM도 128×128 이미지를 봅니다. 이 해상도에서 정확도가 충분한지 P2에서 확인해야 합니다.
