# 용어집 (쉬운 설명)

이 프로젝트 문서에 나오는 용어를 쉽게 풀었습니다. 괄호 안은 영어 원어입니다.

## 로봇·학습
| 용어 | 뜻 |
|---|---|
| **HIL-SERL** | Human-in-the-Loop Sample-Efficient RL. 사람이 옆에서 가끔 개입하면서 실제 로봇이 강화학습으로 배우는 방법입니다. LeRobot에 구현되어 있습니다. |
| **강화학습 (RL)** | 로봇이 시도하고, 보상(잘했다/못했다)을 받으면서 점점 잘하게 되는 학습 방법입니다. |
| **온라인 학습** | 로봇이 실제로 움직이면서 그 자리에서 배우는 것입니다. 오프라인은 이미 모아 둔 데이터로만 배우는 것입니다. |
| **보상 분류기 (reward classifier)** | 카메라 이미지를 보고 "지금 성공 상태인가?"를 0~1 점수로 판단하는 작은 신경망입니다. HIL-SERL은 이 점수로 보상을 줍니다. |
| **임계값 (threshold)** | 분류기 점수가 이 값보다 크면 "성공"으로 봅니다. 기본값은 0.5입니다. |
| **가짜 성공 종료 (false-success termination)** | 실제로는 실패했는데 분류기가 "성공"이라고 판단해 에피소드가 끝나 버리는 것입니다. 로봇이 잘못된 행동을 배우게 만들어서 가장 위험한 오류입니다. |
| **개입 (intervention)** | 학습 중에 사람이 게임패드 등으로 로봇 조종을 잠깐 넘겨받는 것입니다. |
| **에피소드 (episode)** | 로봇이 과제를 한 번 시도하는 처음부터 끝까지입니다(예: 약 20초). |
| **텔레오퍼레이션 (teleop)** | 사람이 리더 암이나 게임패드로 로봇을 직접 조종하는 것입니다. 데이터 수집에 씁니다. |
| **시드 (seed)** | 무작위 과정의 출발 번호입니다. 같은 시드면 같은 결과가 나와서 재현이 가능합니다. |
| **게임패드 (gamepad)** | 게임할 때 손에 쥐고 쓰는 컨트롤러입니다(예: 로지텍 F310). 이 프로젝트에서는 스틱으로 로봇 팔 끝을 움직이고, 버튼으로 집게 열고 닫기, 성공·실패 표시, 개입(조종 넘겨받기)을 합니다. |
| **시연 데이터 (demonstration, offline buffer)** | 사람이 미리 조종해서 성공시킨 에피소드입니다. HIL-SERL은 학습 데이터의 절반(기본값)을 여기서 뽑습니다. 이 프로젝트에서는 그 보상을 조건마다 그 조건의 분류기로 다시 매깁니다(D-29). |

## 라벨링·검토
| 용어 | 뜻 |
|---|---|
| **VLM** | Vision-Language Model. 이미지를 보고 질문에 답하는 AI입니다(예: Qwen3-VL). 이 프로젝트에서는 노트북에서만 돌리고 클라우드는 쓰지 않습니다. |
| **라벨 (label)** | 각 장면에 붙이는 정답 표시입니다. 이 프로젝트에서는 성공 / 실패 / 애매함 / 무효 네 가지입니다. |
| **키프레임 (keyframe)** | 에피소드 영상에서 일정 간격으로 뽑은 장면입니다(예: 0.5초마다 한 장). 라벨은 키프레임마다 붙입니다. |
| **검토 (review)** | 사람이 VLM 제안을 보고 맞으면 그대로 두고, 틀리면 고치는 것입니다. 에피소드 단위로 합니다. |
| **블라인드 라벨링** | VLM 결과를 **보지 않고** 사람이 처음부터 라벨을 다는 것입니다. 평가용 정답을 만들 때 씁니다. |
| **audit 세트** | 최종 평가에만 쓰는 따로 떼어 둔 에피소드 묶음입니다. 사람이 블라인드로 라벨을 답니다. **튜닝이나 선택에는 절대 쓰지 않습니다.** |
| **풀 (pool)** | audit 세트를 뺀 나머지 에피소드입니다(학습용 train + 검증용 val). 검토 예산은 이 풀 기준으로 계산합니다. |
| **누수 (leakage)** | 평가용 데이터의 정보가 학습이나 튜닝에 새어 들어가는 것입니다. 그러면 성능이 실제보다 좋게 보입니다. |
| **검토 정책** | 25%만 검토할 때 어떤 에피소드를 고를지 정하는 규칙입니다. 무작위, VLM 확신이 낮은 것 우선, 가짜 성공 의심 우선이 있습니다. |
| **일치도 (Cohen's kappa)** | 같은 사람이 두 번 라벨을 달았을 때 얼마나 같은지를 나타냅니다. 1이면 완전히 같습니다. |

## 지표·통계
| 용어 | 뜻 |
|---|---|
| **FPR (거짓 양성률)** | 실제 실패인데 "성공"이라고 한 비율입니다. 이 프로젝트에서 가장 위험한 오류입니다. |
| **FNR (거짓 음성률)** | 실제 성공인데 "실패"라고 한 비율입니다. |
| **정확도 (accuracy)** | 전체 중 맞힌 비율입니다. |
| **신뢰구간 (CI)** | "참값이 이 범위 안에 있을 가능성이 높다"는 범위입니다. 데이터가 적을수록 넓어집니다. |
| **부트스트랩 (bootstrap)** | 데이터를 여러 번 다시 뽑아서 결과가 얼마나 흔들리는지 보는 방법입니다. 이 프로젝트에서는 에피소드 단위로 다시 뽑습니다. |
| **짝지은 비교 (paired)** | 같은 평가 에피소드에서 두 조건을 직접 비교하는 방법입니다. 우연에 의한 차이를 줄여 줍니다. |
| **비열등성 (non-inferiority)** | "B가 A보다 정해진 정도(δ) 이상 나쁘지 않다"를 보이는 검정입니다. "성공률 유지"를 통계로 보이려면 이 방법이 필요합니다. |
| **검정력 (power)** | 실제 차이가 있을 때 그것을 찾아낼 확률입니다. 표본이 적으면 낮아서 결론이 "판단 불가"로 나오기 쉽습니다. |
| **Welch t 구간** | 두 조건의 평균 차이에 대한 구간입니다. 두 조건의 흩어짐이 달라도 쓸 수 있습니다. 이 프로젝트에서는 시드별 성공률로 계산해서 온라인 비열등성을 판단합니다(D-30). |
| **반복 실행 (replicate)** | 같은 조건을 시드만 바꿔 여러 번 돌린 것입니다. |

## 이 프로젝트 고유 표현
| 용어 | 뜻 |
|---|---|
| **합성 데이터 (synthetic)** | 컴퓨터가 만들어 낸 가짜 데이터입니다. 프로그램 점검용이며 실제 결과가 아닙니다. |
| **측정 / 시뮬레이션 / 없음** | 모든 숫자에 출처를 표시합니다. 실제로 잰 값(measured), 가짜로 만든 값(simulated), 아직 없는 값(missing)입니다. |
| **한 번 검토, 여러 번 활용** | 사람이 풀 전체(100%)를 한 번만 검토하고, 25%나 0% 조건은 그 기록에서 일부만 꺼내 만드는 방식입니다. 사람 시간을 아낄 수 있습니다. |
| **termination replay** | 녹화된 audit 에피소드에 분류기 점수를 다시 매겨서, 가짜 성공 종료가 몇 번 일어났을지 오프라인으로 추정하는 방법입니다(대략적인 추정치). |
| **bundle** | git 저장소를 통째로 담은 파일 하나입니다. 이력까지 포함되며, 이걸로 노트북에 코드를 옮깁니다. |
