# 보상 라벨 정의: SO-101 pick-and-place (프로토콜 v0.1)

"성공"이 무엇인지 정하는 유일한 기준 문서입니다. VLM 질문문(`labeling/vlm.py`의 `DEFAULT_SUCCESS_DEFINITION`), 사람 검토 도구,
audit 라벨이 모두 이 정의를 따릅니다. **실험 데이터를 모으기 전에 고정하세요.** 나중에 바꾸면 새 프로토콜 버전이 되며,
바꾸기 전과 후의 라벨을 섞어 쓸 수 없습니다.

## 과제
SO-101 팔로 대상 물체 하나(예: 작은 정육면체)를 탁자에서 용기 하나(예: 그릇이나 상자)로 옮깁니다. 데이터 수집 전에 구체적으로 채우세요.

| 항목 | 값 (2026-10-20 승인, 실제 물건을 정하면 색·크기·재질을 적기) |
|---|---|
| 대상 물체 | 한 변 2.5~4cm의 단단한 정육면체, 밝은 단색(예: 빨강). 굴러가지 않는 것. 실제 물건: _(정하면 적기)_ |
| 용기 | 입구가 넓고 낮은 그릇이나 상자(안지름 12cm 이상, 높이 6cm 이하), 물체·탁자와 다른 색. 실제 물건: _(정하면 적기)_ |
| 라벨링에 쓰는 카메라 | `front`(위·앞쪽, 용기 안이 보이게) + `wrist`. 성공 판단은 주로 `front`로 |
| 제어 주기 / 키프레임 간격 | 10Hz / 5프레임마다(2Hz) + 마지막 프레임 |

## 라벨 (키프레임마다)

| 라벨 | 정의 | 학습 목표값 |
|---|---|---|
| **성공 (success)** | 그 순간 세 가지를 모두 만족함: (1) 화면상 물체가 용기 테두리 안에 완전히 들어가 있음 (2) 그리퍼가 열려 있고 물체를 잡고 있지 않음 (가까이 있어도 됨) (3) 물체가 멈춰 있음 (떨어지거나 튀는 중이 아님) | 1 |
| **실패 (failure)** | 장면이 잘 보이고, 성공 조건 중 하나 이상이 분명히 깨져 있음 | 0 |
| **애매함 (ambiguous)** | **이미지만으로는** 판단할 수 없음: 가림(그리퍼나 팔이 물체를 가림), 흔들림, 물체가 테두리에 걸쳐 위치를 알 수 없음 | 학습에서 제외 (개수는 셈) |
| **무효 (invalid)** | 과제에 쓸 수 없는 장면: 검거나 깨지거나 멈춘 영상, 잘못된 카메라, 작업 공간에 사람 손이나 몸(예: 수동 리셋 중), 준비가 안 된 장면 | 학습에서 제외 (개수는 셈) |

### 판단이 어려운 경우의 규칙 (일관되게 적용)
- 물체를 용기 **위에 들고 있음** (바로 위라도): **실패**. 대표적인 "가짜 성공"입니다.
- 물체가 용기 **안에 있지만 아직 잡혀 있음**: **실패** (아직 놓지 않음). 그리퍼가 열리고 물체가 멈추면 성공입니다.
- 물체가 **테두리에 걸치거나 벽에 기대어** 일부가 밖에 있음: 밖으로 나온 게 보이면 **실패**, 정말 판단할 수 없을 때만 **애매함**.
- 물체가 **들어갔다가 다시 밖으로 나감**: 각 키프레임을 그 순간 상태로 라벨링합니다. 그러면 성공 구간 뒤에 실패 구간이 오는 에피소드가 됩니다.
- 물체가 **두 개** 있거나 엉뚱한 물체가 용기에 있음: **무효** (과제 준비가 잘못됨).
- 카메라끼리 다르게 보이면(한쪽은 가리고 다른 쪽은 잘 보임) 잘 보이는 쪽으로 판단합니다.

### 라벨이 의미하지 않는 것
- 정책의 의도나 실력을 평가하는 것이 아닙니다. 그 순간 세상의 상태만 봅니다.
- 진행도 점수가 아닙니다. 거의 성공했어도 **실패**입니다.

## 키프레임 라벨에서 계산하는 에피소드 단위 값
- **에피소드 성공**: 성공 키프레임이 하나 이상 있음
- **성공 시작 시점**: 첫 번째 성공 키프레임 (검토 도구의 "시작 번호" 명령과 termination replay에서 사용)

## 각 과정이 이 정의를 쓰는 방식
- **VLM**: 키프레임마다 yes/no/unsure로 답합니다. unsure는 애매함으로 처리하고, 요청이나 해석에 실패하면 라벨 없음입니다. VLM은 무효를 내지 않습니다.
- **보조 검토** (`hilreview review --purpose pool_review`): 사람이 키프레임마다 VLM 제안을 보고 받아들이거나 고칩니다.
- **블라인드 audit** (`--purpose audit`): 사람이 VLM 출력 없이 라벨링합니다. 일부를 블라인드로 한 번 더 라벨링해서(`--purpose audit_repeat`) 일관성(Cohen's kappa)을 잽니다.
- 자동 점검에서 무효로 나온 키프레임은 모든 조건에서 무효로 고정됩니다.
